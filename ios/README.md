# iOS: StarSplat and RC Probe

Instructions for an agent (or a person) helping someone with an iPhone get set up. Two apps live here:

| App | What it is | How it gets to a phone |
|---|---|---|
| **StarSplat** (`FlightLab/`, bundle `com.clarksaben.starsplat`) | Full-screen web view of the Flight Lab sandbox at `https://dji.clarksaben.com/sandbox.html`: scenes, on-phone flying, races, videos. No drone control. | TestFlight |
| **RC Probe** (`RCProbe/`, bundle `com.clarksaben.rcprobe`) | Read-only test app that talks DJI's DUML protocol to the DJI RC-N1 remote over the phone cable. Step 1 of flying the Mini 3 directly from an iPhone. | Development install from a Mac (or sideload, see Windows) |

The project is generated: edit `project.yml`, then run `xcodegen generate` (`brew install xcodegen`). Never edit `FlightLab.xcodeproj` by hand.

## Rules

- **No keys in the repo or in chat logs.** The gateway has an owner key and a guest key on cradle (`~/.config/dji-gateway/`). The owner decides who gets which. Give testers the **guest** key; it can't make paid splats, train races or fly the real drone.
- **No location data** (home coordinates, nearby place or airport names) in commits, logs, screenshots or messages.
- **RC Probe stays read-only.** It sends version requests (`00/01`), stick reads (`06/01`) and the link keepalive (`06/77`). Do not add flight, camera or settings writes without the owner's say-so, and test any flight command with **props off** first. Never touch geofencing, altitude limits, region/FCC settings or return-to-home.

## StarSplat: getting a new tester on

The app is already in App Store Connect (team `ZHQPRX6ZHB`, Individual account). The owner does these steps in the App Store Connect web UI, because they need their Apple login:

- **Internal tester (no Apple review, works as soon as the build has processed):** add the person under *Users and Access* with a minimal role (Customer Support) and access to StarSplat only. They accept the email invite. Then add them to the internal group (currently "developers") in *TestFlight*.
- **External tester (needs Apple beta review, about a day for the first build):** add their email to an external group that has the current build.
- The tester installs **TestFlight** from the App Store, accepts the invite, installs StarSplat, and types the guest key into the login screen once (the cookie lasts 180 days).

Shipping a new build (only needed for native changes: icon, name, Swift code). Web changes go live on cradle without a new build.

```sh
ios/upload_testflight.sh     # archive, sign, upload; App Store Connect bumps the build number
```

Then add the build to the groups in App Store Connect. The icon is `icons/starsplat-icon.png` (pixel night "P7"), generated by `icons/pixel.js`; `icons/index.html` is the picker page.

## RC Probe: first contact with the remote

Goal: find out whether an iPhone can talk to the RC-N1 and, through it, to the Mini 3. Prior work (read for facts; their code is not licensed for copying here):
- [AStoker/ios-dji-rc-n3-inputs](https://github.com/AStoker/ios-dji-rc-n3-inputs): RC-N3 on iOS opens as External Accessory `com.dji.logiclink` in a dev build with no MFi gate; DUML inside `55 CC` envelopes on port 22345; sender must be App (0x02).
- [andreapianidev/DJI-FCC-Unlock-iOS](https://github.com/andreapianidev/DJI-FCC-Unlock-iOS): commands reach the aircraft through the remote from iOS; keepalive `06/77` every 2.5 s. RC-N1 untested.
- [doesthings/FreeFCC-USB](https://github.com/doesthings/FreeFCC-USB): on Android the Mini 3's RC-N1 only talks over AOA on the top (phone) port.

### Needs

- An iPhone (Lightning or USB-C) and the cable that came with the RC-N1 for that phone.
- **Developer Mode** on: Settings → Privacy & Security → Developer Mode (the phone restarts).
- A Mac with Xcode, signed in to the team's Apple ID (Xcode → Settings → Accounts). For Windows, see below.

### Install (Mac)

1. Plug the iPhone into the Mac, unlock it, tap **Trust**.
2. Run `ios/install_probe.sh`. It finds the real iPhone, registers it with the team (automatic signing), builds, installs and launches.
3. If iOS says the developer isn't trusted: Settings → General → VPN & Device Management → trust it.
4. Development builds expire after about a year on a paid team; rerun the script to refresh.

### Run the test

1. Force-quit **DJI Fly** (only one app can hold the remote).
2. Plug the iPhone into the RC-N1's phone cable and turn the remote on.
3. Expect *Connected over com.dji.logiclink* (or another `com.dji.*`), and the **Sticks** bars moving.
4. Turn the drone on, on the ground. Wait 20 s. Check **Who answered**: `flight`, `gimbal`, `camera`, `battery` answering means the aircraft is reachable from the phone.
5. **Share log** (AirDrop to a Mac). The log lists the accessory, the session, every new message type and every version reply.

### Reading the result

| What you see | Meaning | Next |
|---|---|---|
| Accessory: None | iOS doesn't see the remote | Check the cable/port (the remote's phone cable), the remote is on, DJI Fly closed |
| Remote found, session refused | iOS blocks the protocol for this app | Compare the remote's protocol strings in the log with `RCProbe/Info.plist`; add any missing one |
| Connected, no frames | Envelope or sender is wrong for the RC-N1 | Try bare DUML (no envelope) and port 30000 in `Link.swift` |
| Sticks move, only `remote`/`link-gnd` answer | Remote works, aircraft not reached (or drone off) | Turn the drone on; check `link-air` |
| `flight` answers | The phone can reach the flight controller | Start decoding telemetry (OSD push, set 0x03) and, props off, flight commands |

### Code map

- `RCProbe/DUML.swift`: frame build/parse (CRC8 seed 0x77, CRC16 seed 0x3692, both reflected), the `55 CC` envelope (`port LE16`, `length LE32`). Checked against known RC-N1 frames.
- `RCProbe/Link.swift`: External Accessory session, read/write pumps, parsing, the read-only requests, the log file (also visible in the Files app).
- `RCProbe/RCProbeApp.swift`: the screen.

## Windows instead of a Mac

Building needs Xcode, which only runs on macOS, but **installing** doesn't:

- **Sideload a prebuilt app.** Someone with a Mac (or a macOS CI runner) builds an unsigned `.ipa` once. On Windows, [Sideloadly](https://sideloadly.io) signs it with the tester's own Apple ID and installs it over the cable. That's how DJI-FCC-Unlock-iOS ships. A free Apple ID works, but the app expires every 7 days and must be re-sideloaded; a paid developer account lasts a year. Developer Mode is still required.
- **Build in the cloud.** GitHub Actions has macOS runners, so a workflow can build the unsigned `RC Probe.ipa` on every push and attach it to a release; a Windows user only needs Sideloadly. (Not set up yet.)
- **StarSplat** needs neither: testers install it from TestFlight on any phone.

Building the unsigned IPA on a Mac:

```sh
cd ios && xcodegen generate
xcodebuild -project FlightLab.xcodeproj -scheme RCProbe -configuration Release -destination 'generic/platform=iOS' \
  -derivedDataPath build CODE_SIGNING_ALLOWED=NO build
mkdir -p build/ipa/Payload && cp -R "build/Build/Products/Release-iphoneos/RC Probe.app" build/ipa/Payload/
(cd build/ipa && zip -qr ../RCProbe-unsigned.ipa Payload)
```
